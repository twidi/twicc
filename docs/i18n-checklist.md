# Interface internationalization checklist

This file records the file-by-file frontend and backend interface audit.
Keep this file uncommitted until the complete pass and its reviews finish.
Commit the completed checklist together with the validated translations.

## Meaning of a checked item

A checked item has an implementation audit and an independent review.
Read each source file in full, including imported display values and script-generated UI.
A checked source file can contain no interface text. Its display paths still require review.

## Scope

### Application sources

Include frontend application Vue, JavaScript, TypeScript and CSS sources, plus translation catalogs.
Include backend application Python sources that implement or support browser-facing behavior.
Read shared dependencies even when they live under CLI or MCP directories.
Narrow native-client transport dependencies belong here when they carry these browser messages.
This does not claim a complete native Android interface audit.
Include standalone entry points and HTML that displays application messages.
Keep `frontend/vite.config.js`: it injects catalog messages into the startup recovery interface.
Keep help/tip interface components and metadata sources. Their controls and titles are translated.
The catalogs contain 12 help titles and 54 tip titles per locale; they contain no Markdown bodies.
Include help/tip Markdown sources in the content inventory, with one checkbox per English source.
Each content entry covers the English file and all translated bodies under locale subdirectories.

### Deliberate exclusions

Apply these rules to existing files and new files during every pass.
An excluded file is not missing, unchecked or awaiting review. Give it no checkbox.

| File type | Recognition rule or example | Reason |
| --- | --- | --- |
| Images and video | PNG, ICO, SVG, WebP, MP4; icons, screenshots and release media | Media is outside this source pass. |
| Help/tip authoring guides | `frontend/public/help/README.md`, `frontend/public/tips/README.md` and equivalent contributor guides | Contributor documentation stays English; actual Markdown content belongs in the content inventory. |
| Translated content entries | Locale subdirectories such as `frontend/public/help/pt-BR/` and `frontend/public/tips/pt-BR/` | Review these as dependencies of their English source entry. Do not add separate checkboxes. |
| Static public assets | Public media and `frontend/public/site.webmanifest` | Asset metadata has no interface messages in the current application. |
| Tests and harnesses | `*.test.*`, `*.spec.*`, `frontend/tests/`, `__tests__/` | Test text is not production interface copy. |
| Test fixtures | `__fixtures__/`, fixture-only data such as `GitLog/__tests__/fakeData.ts` | Synthetic data is not application interface copy. |
| Benchmark data | `frontend/src/data/modelBenchmarks.json` and equivalent numeric/model benchmark datasets | Values, model identifiers and reference URLs are not interface prose. |
| Package metadata | `package.json`, `package-lock.json` and equivalent dependency manifests/lockfiles | Package metadata does not supply interface messages. |
| Tooling and build configuration | TypeScript/ESLint configuration and Vite bundle configuration without interface messages | These files configure development or bundling. |
| Backend-only outputs | Console logs, terminal output, CLI/MCP replies, prompts and provider transcripts | Keep English prose and original content. |
| CLI/MCP-only sources | Command wrappers and protocol-only modules without a browser consumer | Exclude by role; shared browser dependencies remain in scope. |
| Backend tests and migrations | `tests/`, test settings, database migration files and test fixtures | Verify these separately; they are not interface source inventory. |
| Deliberately English pages | Public sharing; standalone share/artifact password forms; unavailable-share page; `/mcp/oauth/wait` | No translation work is required. See the exact sources and boundaries in `docs/internationalization.md`, **Pages that deliberately stay English**. |
| Pages outside the application | `telemetry-collector/public/index.html` and standard Django error pages | Outside the interface translation scope. |
| Generated files and dependencies | Build output, caches and `node_modules/` | Audit application sources instead. |

Classify files by their role, not only their extension or directory.
Discovered command descriptions and the default labels "Custom command", "Skill" and "Workflow" deliberately stay verbatim.
Audit their source files normally, but do not report these labels as missing translations or add command metadata fields.
Do not exclude runtime display dictionaries as fixtures or benchmark data.
Do not exclude application code because its current audit finds no interface text.
Public executable code or configuration that supplies interface messages belongs in scope.
The explicit English-page exclusions take precedence over this general rule.
Keep shared modules in scope when they also supply application interface messages.
MCP approval, telemetry dialogs/settings and sharing controls inside TwiCC remain in scope.
Existing translations in public Vue viewers do not create a requirement to localize public sharing.
If a file changes role, reassess its exclusion and add it when it becomes application source.
For an unknown file type, inspect its role before deciding whether it belongs in scope.

## Lifecycle

The last commit that modifies this file must represent a completed pass.
At the start of a later pass, uncheck all entries in the working copy.
Use that commit as the baseline; do not use a date or the current branch tip.

1. Find the baseline with `git log -1 --follow --format=%H -- docs/i18n-checklist.md`.
2. Compare frontend and backend files, plus recorded native transport dependencies, against that commit, including staged and unstaged changes.
3. Enumerate untracked source files too; a Git diff does not list them.
4. Apply the scope and exclusion rules before comparing files with this inventory.
5. Add every new in-scope file as unchecked. Remove deleted entries and update renamed paths.
6. Audit changed files in full and review their affected display dependencies. English help/tip changes reopen their content entry and all translations. Translation changes reopen the corresponding English entry.
7. Carry unchanged files forward only when their display dependencies remain valid; then check their entries again.
8. Complete the reviews and validation. Commit the fully checked inventory with the translations.

Never add an excluded file merely because it is absent from this inventory.
Do not commit a partially completed checklist. Its next commit becomes the next baseline.
