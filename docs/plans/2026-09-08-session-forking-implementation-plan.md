# Session Forking Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking. Execution remains a separate user authorization; this delivery creates the plan only.

**Goal:** Create independent conversation branches with fixed boundaries, composed inherited history, correct ownership, and navigation between branches.

**Architecture:** Keep provider records in revision-scoped storage. Build paginated conversation indexes containing references and derived metadata, never synthetic inherited message bodies. Provider adapters certify boundaries and native operations; one scope-aware reader serves owner UI and shares. Durable creation and first-send journals handle failures independently.

**Tech Stack:** Python ≥3.13, Django 6, SQLite/WAL, Channels, orjson, existing provider SDKs; Vue 3, Pinia, IndexedDB, Web Awesome, existing virtual scroller; pytest/pytest-django and node:test.

## Global Constraints

- Each branch is a separate TwiCC session on the same provider.
- Opening or abandoning a draft never calls a provider fork operation.
- A later source append never extends the retained history, including for a fork-at-end draft.
- Do not create child `SessionItem` copies of ancestor records to make a fork appear linear.
- Native Claude copied records remain authoritative for the child's snapshot; they are ingested once as native records.
- A native API is not assumed idempotent. Unknown creation and dispatch outcomes independently stop automatic retries.
- Forking does not restore workspace files. No automatic worktree, cross-provider fork, or destructive provider-file rewrite.
- Graph overview, extra sidebar marker, rewind action, and CLI/MCP creation remain deferred.
- First-user-request fork-before remains unavailable in v1; completed-turn forks remain available.
- No new unconditional Claude mid-turn prohibition. Provider contract gates determine concurrent operation support.
- Research baseline: Codex `0.153.4`; Claude SDK `0.2.152` / CLI `2.1.259`. Recheck actual pins before execution; do not silently change dependencies.
- All code, comments, UI strings, tests, and repository documents are English.
- Stay in the current checkout unless the user explicitly requests a branch/worktree.
- Preserve unrelated user changes. Never install dependencies, restart servers, or apply migrations to the running instance without the user's instruction.
- Main-checkout tests: `uv run pytest`; frontend tests: `cd frontend && npm test`. Use `uvx ruff check` if lint is run, not `uv run ruff`.
- In an explicitly authorized worktree, prefix shell commands with `cd <worktree> &&` and use `TWICC_DATA_DIR=$PWD` for project Python commands. Never use `uv --active` or `uv pip`.
- New schema migrations are generated by name against the actual graph. Current inspected leaf is `0143_alter_mcpoperation_created_at`; never hardcode that leaf if the graph changes.

## 2. Concrete data design

These decisions resolve the spec's implementation choices. Create models in `src/twicc/core/models.py`; helper behavior belongs in `src/twicc/history/` and `src/twicc/forks/`.

### 2.1 Revision-scoped records; no second transcript table

Extend **SessionItem**, rather than creating a parallel raw-message store:

- `stream_revision`: FK to `HistoryRevision`, nullable in this release for online backfill; required by the ready-namespace writer after backfill; `PROTECT`.
- `record_key`: immutable UUID, unique after backfill. New records use UUID4; existing records receive UUIDs in batches.
- Existing `line_num`: physical line within that revision, never logical display position.
- Existing `session`: native owning Session, retained for legacy compatibility and ownership queries.
- `source_digest`: SHA-256 of the original complete JSONL line, before TwiCC rendering enrichment.
- `native_anchor`: JSON dictionary containing adapter indexes, such as scoped UUID/turn/ordinal; not a global uniqueness constraint.
- Existing `content`: provider record payload; add `content_format` (`legacy_enriched_v1/native_v1`). New history ingestion preserves source content; move render transformations to derived rendering output.
- Existing cost/display fields become legacy migration inputs or single-record hints, not the authoritative projection/charge fields.

Add unique `(stream_revision, line_num)` in T02. Remove `unique_session_line` in T04 migration `history_stream_keys`. This schema migration performs no backfill-readiness check.
This permits T04–T18 tests to exercise coexisting revisions. Intermediate commits are not deployable; production multi-revision admission remains gated until T19 verifies every reader.
Preserve original SessionItem PKs and link mappings during backfill.
`source_digest` may be empty for historical DB-only records whose original provider bytes cannot be verified; never invent a proof from transformed content.

### 2.3 Projection materialization choice

Materialize **reference indexes** in ProjectionEntry, not inherited message content.
A fork copies record references from its retained projection prefix using bounded `INSERT ... SELECT`/batched ORM operations.
For Claude native copied records, reference the child record, not the current parent body; provenance still marks it inherited.
For Codex, inherited entries reference ancestor records. Native-only header/init records are classified and do not duplicate visible context.

Projection builds run in chunks of 500 references and never expose `building` rows to readers.
Queries read position ranges using the unique `(projection, position)` index. Page content fetches only those record PKs.
Store grouping references and render-context descriptors, not rendered text bodies. Provider replacements are applied from captured native records at render time.
A single caller never recursively loads all ancestor content to return one page.
This uses O(projected records) index space, but O(native records) body space. Measure index growth in T20.
