TwiCC anonymous telemetry

Self-hosted TwiCC installs send anonymous usage statistics to this endpoint once a day. It is enabled by default, and can be turned off in one click from the app's settings.

Why it exists

These statistics are the only way for TwiCC's author to know how the project is actually used — how many installs are alive, how regularly and intensely they run, at what scale, on which platforms — and to decide where to spend the effort. If you leave telemetry enabled: thank you, it genuinely helps.

The telemetry code is open source like the rest of TwiCC, in the TwiCC repository, so anyone can verify that it does nothing more than what this page describes.

What is collected

One JSON document per day, built from two parts: an instance block sent with every payload, and a daily block for each not-yet-sent complete day (UTC). Fields contain counters, booleans, enums, buckets, and version metadata. One configuration value is sent verbatim: the active, validated OpenRouter TTS model identifier. No model allowlist restricts future models.

Most values come from the database and saved configuration. The four summary/TTS counters and active client descriptions use limited instrumentation. These aggregates live in the local telemetry.json file, with no event log or new database tables. New metrics start with the next complete UTC day; older blocks omit them instead of reporting false zeros. Collection stops before notice acknowledgement and while telemetry is disabled. Local daily aggregates retain at most 30 complete UTC days plus today's partial entry. Periodic cleanup removes older dates even while collection is disabled.

A device here means a browser profile or Android client installation, not a physical device. Tabs and reloads share a random local profile key. Daily salted digests deduplicate profiles locally; neither keys, digests, salts, nor raw User-Agent values reach this collector. Two browsers on the same computer count separately. Clearing browser storage creates a new profile. Identical descriptions are grouped with their exact counts. Web Locks serializes first key creation between tabs on HTTPS or localhost when available. Without that API, including HTTP on a LAN, simultaneous first tab openings can create separate keys and overcount a profile. Without browser storage, identity lasts only for the current page. Counts are exact for the observed keys, subject to these profile limitations. Native activation counting requires an Android app that forwards the collection epoch; older app versions omit this counter contribution.

What is never collected

  • No message or prompt content, no session titles
  • No project names or file paths, no git data
  • No hostnames, usernames, or email addresses
  • No IP addresses — the client never sends one, and this collector does not log or store any
  • No exact costs or token counts, only buckets
  • No per-session identifiers of any kind — only aggregate counters
  • No client identifiers, hardware identifiers, raw User-Agent, or browser versions

The instance identifier

instance_id is a random UUID v4, generated locally the first time telemetry runs. It is derived from nothing about the machine or its owner — no MAC address, no hostname hash — so it identifies nothing beyond making distinct instances countable. A "Reset instance ID" action in settings regenerates it at any time, severing any history tied to the old one.

How to disable it

Turn off the toggle at the bottom of the General section in TwiCC's settings panel, or set the environment variable TWICC_NO_TELEMETRY=1 before starting the backend, which initializes the setting to off once per instance. You can enable it again in settings, and that choice survives backend restarts.
